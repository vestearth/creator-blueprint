# Canonical Narrative

Status: `draft-complete-pending-human-verification`

นี่คือ narrative กลางที่ไม่แบ่งตามจำนวน card หรือรูปแบบแพลตฟอร์ม

## Working title

Prompt เก่งแค่ไหน ก็ยังไม่ใช่ AI Agent

## Audience promise

เราจะเห็นความต่างจาก “วิธีที่ระบบเดินงาน” และเลือกได้ว่าโจทย์ไหนแค่คุยกับ AI ก็พอ
โจทย์ไหนควรมี Agent

## Hook concept

คำตอบที่ดีไม่ได้แปลว่างานเสร็จ Prompt ต่อให้ละเอียดก็ยังเป็นเพียงการบอกทิศทาง
ถ้าระบบไม่มีทางลงมือ ดูผล เก็บความคืบหน้า และตรวจว่าถึงเป้าหมายแล้วหรือยัง

## Reasoning order

1. แยกหน้าตาแชตออกจากพฤติกรรมของระบบ
2. แสดงเส้นทางสั้นของ Chat ทั่วไป `Prompt → Answer`
3. แสดง execution loop ของ Agent
4. อธิบายสิ่งที่ prompt อย่างเดียวไม่มี: action, observation, state และ control loop
5. แจกแจงส่วนประกอบโดยไม่ทำให้ model กับ Agent เป็นสิ่งเดียวกัน
6. ใช้โจทย์ “หาข้อมูลแล้วทำรายงาน” ให้เห็นผลลัพธ์ต่างกัน
7. ให้เกณฑ์เลือก chat / workflow / Agent
8. เชื่อม tools และ data ไปสู่ MCP เป็นหัวข้อถัดไป

## Main explanation

คำว่า Agent ยังไม่มีนิยามเดียวในอุตสาหกรรม บางแห่งรวม workflow ที่กำหนดขั้นไว้
ล่วงหน้าไว้ในคำว่า agentic system ขณะที่บางแห่งสงวนคำว่า Agent สำหรับระบบที่ให้
โมเดลเลือกกระบวนการและเครื่องมือเองมากขึ้น [C-001] เพราะฉะนั้นสิ่งที่มีประโยชน์กว่า
การจำศัพท์ คือดูว่า “ระบบทำงานอย่างไร”

การคุยแบบ chat ทั่วไปเริ่มจากเราให้คำถามหรือ instruction แล้ว model ตอบกลับจาก
context ที่มี การตอบอาจดีมากและ prompt ที่ชัดช่วยให้ผลลัพธ์ดีขึ้น แต่เส้นทางหลักยัง
จบที่คำตอบของรอบนั้น

ระบบแบบ Agent รับ goal และทำงานผ่านหลายขั้น โดยเลือก next step ใช้ tool หรือทำ
action เมื่อจำเป็น รับผลจาก environment กลับมา ประเมินความคืบหน้า แล้วทำต่อหรือหยุด
ตามเงื่อนไข [C-002, C-005] Runtime ของ Agent ยังอาจจัดการ state, history, approval,
handoff และการ resume งานที่ยังไม่จบ [C-003, C-004, C-012]

จุดนี้ทำให้ “prompt เก่ง” ยังสำคัญ แต่ไม่เท่ากับ Agent เพราะ prompt ช่วยกำหนดเป้าหมาย
ข้อจำกัด รูปแบบผลลัพธ์ และวิธีคิด ส่วน Agent ต้องมี tools, state และ feedback loop รอบ
model เพื่อให้เกิดการลงมือและตัดสินใจทำต่อจากผลจริง [C-003, C-010]

ภาพจำที่ใช้งานได้คือ Agent ไม่ใช่ model เดี่ยว ๆ แต่เป็น model ที่ทำงานภายในระบบซึ่งมี:

- Goal/instructions: เป้าหมายและขอบเขต
- Context: ข้อมูลที่ต้องใช้กับงานตรงหน้า
- Tools/actions: ช่องทางค้น อ่าน เขียน คำนวณ หรือทำงานกับระบบภายนอก
- State/memory: งานทำถึงไหน ผลไหนต้องส่งต่อ และจะกลับมาทำต่ออย่างไร
- Workflow/control: การจัดลำดับ วนซ้ำ approval และ stopping condition
- Verification: เช็กผลกับหลักฐาน test หรือ human review ก่อนถือว่างานเสร็จ

ตัวอย่าง “หาข้อมูลแล้วทำรายงาน” ถ้าใช้ chat เราอาจได้โครง คำแนะนำ หรือ draft จาก
ข้อมูลที่ป้อนให้ แล้วเราเป็นคนค้นแหล่ง เปิดลิงก์ สร้างไฟล์ และตรวจความครบถ้วนเอง
แต่ถ้าเป็นระบบ Agent ที่มีสิทธิ์และเครื่องมือเหมาะสม มันอาจแตก goal เป็นขั้น ค้นและ
บันทึกแหล่งข้อมูล สร้างไฟล์ เปิดผลลัพธ์ ตรวจตาม checklist และวนแก้ก่อนส่งให้คน review
[C-011] ความต่างจึงไม่ใช่แค่ “คำตอบยาวกว่า” แต่เป็นขอบเขตของงานที่ระบบทำได้จริง

อย่างไรก็ตาม ไม่ใช่ทุกงานต้องใช้ Agent งานถามความหมาย สรุปข้อความ rewrite ระดมไอเดีย
หรือขอคำอธิบายหนึ่งรอบ มักได้ประโยชน์จาก chat ที่เร็ว เรียบง่าย และควบคุมง่ายกว่า
Agentic systems เพิ่ม latency, cost และโอกาสที่ความผิดพลาดจะทบกัน จึงควรเพิ่มความ
ซับซ้อนเมื่อโจทย์ต้องเดินหลายขั้นจริง ๆ [C-006]

Agent มีประโยชน์เมื่อโจทย์ปลายเปิด จำนวนขั้นคาดเดายาก ต้องใช้หลายแหล่ง/หลายเครื่องมือ
ต้องแก้จาก feedback หรือมีเกณฑ์ตรวจชัด เช่น research ที่ต้องรวบรวมหลักฐาน coding ที่
รัน test แล้วแก้ต่อ หรือ workflow ที่ต้องอ่าน–เขียนไฟล์และทำ action ข้ามแอป [C-005,
C-007] งานที่เส้นทางตายตัวและต้องการความสม่ำเสมออาจเหมาะกับ workflow ที่เขียนกฎไว้
มากกว่าปล่อยให้ Agent เลือกทุกขั้น [C-001, C-007]

เมื่อ Agent ต้องเข้าถึงข้อมูลและเครื่องมือภายนอก คำถามถัดไปคือจะเชื่อมสิ่งเหล่านี้อย่างไร
MCP เป็นมาตรฐานการเชื่อมต่อที่เปิดให้ AI application ใช้ Resources, Tools และ Prompts
[C-008] แต่ MCP ไม่ใช่ Agent runtime และไม่ได้แทน permission หรือ verification ที่
application ต้องออกแบบเพิ่มเติม [C-009]

## Recommendation or conclusion

อย่าเริ่มจากคำถามว่า “ควรใช้ Agent ไหม” ให้เริ่มจากงาน:

1. ต้องการแค่คำตอบ หรือให้ระบบลงมือจนเกิดผลลัพธ์?
2. มีหลายขั้นที่ขึ้นกับผลของขั้นก่อนหรือไม่?
3. ต้องเรียกข้อมูล เครื่องมือ ไฟล์ หรือแอปภายนอกหรือไม่?
4. ต้องเก็บ state และ resume งานหรือไม่?
5. มีวิธี verify และจุดที่ต้องให้คนอนุมัติหรือไม่?

กรอบจำแบบสั้นคือ รู้คำตอบที่ต้องการให้เริ่มจาก Chat รู้ขั้นตอนที่ต้องทำให้เริ่มจาก
Workflow และถ้ารู้เป้าหมายแต่ต้องตัดสินใจระหว่างทาง Agent อาจช่วยลดภาระการคุมงาน
ทีละขั้นได้ โลกจริงทั้งสามแบบสามารถทำงานร่วมกันได้

## Caveats

- หน้าตาแชตไม่ได้แปลว่าระบบไม่มีพฤติกรรมแบบ Agent
- Agent ไม่ได้หมายถึง autonomous 100%; checkpoint และ human approval เป็นส่วนสำคัญได้
- Tools เพิ่มความสามารถและความเสี่ยง จึงต้องจำกัดสิทธิ์และตรวจผล
- Prompt engineering ไม่ได้ล้าสมัย; prompt เป็นส่วนหนึ่งของระบบ แต่ไม่ใช่ทั้งระบบ
- คำแนะนำนี้เป็น mental model สำหรับเลือก workflow ไม่ใช่มาตรฐานจำแนกผลิตภัณฑ์

## CTA intent

ชวนคนดูแยก “งานที่แค่อยากได้คำตอบ” ออกจาก “งานที่อยากให้ AI ลงมือจนเสร็จ” และ
ถามว่าต้องการให้ทำตอนต่อเรื่อง MCP ซึ่งอธิบายสะพานเชื่อม Agent กับ tools/data หรือไม่
